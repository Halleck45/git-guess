In CI: label every pull request from its diff

  
# .github/workflows/git-guess.yml
on: [pull_request]
permissions: { contents: read, pull-requests: write }
jobs:
  guess:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }
      - uses: Halleck45/git-guess@v1

  
Adds enhancement, bug, documentation… to the pull request, and lints its commits: a commit without a type gets a suggestion, a commit declared docs whose diff is clearly code is flagged. All the options.






  
Honest about what it knows

  

    
Trained on 488,000 commits
from 244 open-source projects across every ecosystem that uses Conventional Commits. Measured on repositories it had never seen, split by repository, not by commit.

    
It learns your repository
The closest past diffs, what your project calls what, which files go with which type. Indexed once in .git/, refreshed incrementally.

    
It asks when it is not sure
feat against fix against refactor is intent, not content. Above 90% confidence it is right 96% of the time; below 55% it offers the two best candidates.
